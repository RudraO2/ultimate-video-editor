The model (format 16, all optional, no conversion):
- **Switch:** group field `switch: number | null` (null = a plain group). Keyable number property `switch` (keys hold; the value rounds down) = index of the member shown, counted from the top (front). Commands take a member's name or index. The group's box stays the union of all members, so its pivot never jumps.
- **Rig:** group field `rig: {bones: Bone[]}`; `Bone {id ('bone_'), name, head: [x, y], tail: [x, y] (comp px, the group's own space before its transform), parent: id | null, deform: boolean (false = a control), limits?: {rotation?, x?, y?, scale?: [min, max]}, ik?: {target: boneId, chain: 1 | 2, flip: boolean, mix: 0..1} | null}`. Pose channels are keyable number properties of the rig group: `bone.<id>.rotation|x|y|scale` (deltas from rest; scale = stretch along the bone, 1 rest). Member field `bind?: {mode: 'auto' | 'rigid' | 'none', bone?: id}` on direct members of a rig. Auto: the deform bone running furthest through the member's box rides it; a bone that only starts in it gives its parent; none touching: the nearest. Children inherit the parent's turn and move; a parent's stretch moves the child's joint but does not stretch the child.
- **Behaviours:** group field `behaviors: Behavior[]`, `{id ('bhv_'), type: 'blink' | 'breathe' | 'sway' | 'nod' | 'glance' | 'talk', enabled, target: {layer?: id, bone?: id}, ...fields}` (each type its own strict schema: seed, every, amount, periodMs, pivot [x, y], voice layer id or null). Pure math in core `characters.ts` (blink schedule, seeded waves, glance holds, talk blocks from an envelope), applied by the engine in `scene.ts` each frame: bone channels add to the pose, layer targets get a matrix about a pivot (squash for blink, scaleY about the bottom for breathe), talk sets a mouth switch. Same inputs, same frames.
- **Envelope:** media field `envelope?: {rate: 50, values: number[]}` (0..1 loudness, 20 ms steps), traced in the app from decoded audio like `silhouette` (`Session.envelope` hook), so talk and nod are pure functions of the document.

## Plan of A10.9 (motion paths), in chunks

This plan comes from the research ("Motion paths" in the research notes). The design:
- `KeyframeSchema` gets an optional `spatial: {in: [dx, dy] | null, out: [dx, dy] | null}`.
- It is allowed on `transform.x` keys only, and only where a `transform.y` key sits at the same time (within 0.5 ms).
- Position stays two tracks, so every existing reader keeps working.
- A segment between two motion keys is curved when either end has a handle. A missing handle is a third of the chord toward the other key. The point is the cubic Bézier at the eased time, using the easing of the start key's x key.
- Straight segments are unchanged.
- No auto-orient and no constant speed (AtomCut has neither; they could come later).

Chunks, each one chat:
- **A10.9b: core schema and evaluation, with tests.**
  - Schema: `spatial` on `KeyframeSchema`, with the check that it sits on x keys that have a y partner (in the commands that write keys and in `checkStructure`, if there is one). Project file format 7, with no conversion (old files read as they are).
  - New `packages/core/src/motionPath.ts`, pure:
    - `motionKeysOf(layer)`: rows `{t, x, y, ease, in, out}` from the paired x/y keys;
    - `hasMotionPath(layer)`;
    - `motionPointAt(layer, t)`: `[x, y]`, or undefined when the segment at `t` is straight;
    - `arcHandles(a, b, arc)`: the parabola control point, then `out = ⅔(C − A)` and `in = ⅔(C − B)`, peaking at `min(yA, yB) − arc`, or at `max(yA, yB) + |arc|` when negative;
    - `splitSegment(seg, u)` (de Casteljau, for insert);
    - `smoothTangents(prev, cur, next)` (`(next − prev) / 6`);
    - `bendHandles(seg, u, point)` (u clamped to 0.1…0.9).
  - `evaluateProperty` (`properties.ts`) returns the curve's x or y for `transform.x` and `transform.y` when the segment at `t` is curved, so the engine, motion blur, `keyframes.clear` freezing, `layer.set` auto keys and simplify's sampling all see the curve.
  - Commands that drop keys must drop the curve that needs them:
    - `keyframes.remove` of an x key, or of the y key paired with a curved x key, clears that `spatial`;
    - `keyframes.clear` drops `spatial`;
    - `keyframes.simplify` leaves a position pair with any `spatial` alone and reports it as skipped.
  - Tests:
    - the worked example: A (0, 0), B (300, 0), arc 100 gives out (100, −133.3), in (−100, −133.3) and a peak at −100;

    - a negative arc;

## Plan of A7 (3D worlds), in chunks

This plan comes from the research ("3D worlds (step A7a research)" in the research notes). The order puts the milestone first: a 2D title moves into a world with no visual jump, and a camera flies around it (A7b to A7d). It is then usable by hand and by agents (A7e, A7f) before the look is deepened.

### The design
- **Document.**
  - `Comp.world?` holds `render` (`toneMapping`, `exposure`, `shadows`, `shadowQuality`, `bloom`, `ao`, `floor`) and `fog`, with AtomCut's defaults. A comp is a world exactly when it has `world`.
  - Space: Z up, X right, Y away from the front view, 1 unit = 1 px.
  - New layer kinds, allowed only in worlds:
    - `camera` (a `camera` field);
    - `light` (a `light` field);
    - `empty` (a controller);
    - `mesh` (A7h).
  - 2D layers in a world are picture planes.
  - The transform gains `scaleZ`.
  - Project file format 8.
- **Matrices.**
  - T·Rz·Ry·Rx·S in degrees, which is our `layerMatrix` order.
  - A picture plane scales by `[scaleX, scaleZ, scaleY]` and lies in the XZ plane, facing −Y.
  - Cameras and lights look down their local −Z.
  - The default camera sits at (0, −D, 0) with rotation [90, 0, 0], where D = max(w, h) · 50 / 36. This is our `frontCamera` distance.
  - The field of view is sensor-fit on the longer side.
  - The live camera is the topmost visible camera clip that covers the time.
- **World math lives in core** (pure, no DOM, own small 4×4 helpers): `packages/core/src/world.ts`. The commands (`world.inspect`) need it, and the engine reuses it.
- **Rendering.**
  - three.js is a dependency of `packages/engine`, behind a dynamic import (`engine/src/world/`). Flat projects never load it.
  - A world draws onto one shared `WebGLRenderer` canvas. `CompRenderer` then `drawImage`s that canvas into the flat comp, the same way for the viewport, `view_*` and export.
- **Command names** follow AtomCut's tools: `world.create`, `world.add`, `world.inspect`, `world.camera`, `world.move_into`, `world.look`, `world.material`, `world.extrude`, `world.track`, plus the host tool `world_import_model`.
  - Each refuses a flat comp with AtomCut's message: `"<name>" is a flat comp, not a 3D world.`, with a hint to use `world_create`.
- **Phase E, not A7:** modifiers, `world_apply_modifier`, `world_lattice`, `world_sculpt`, `mesh_edit`, booleans, `world_line_art`, `world_face` and the head kind, IK, physics in worlds, and model export (glTF, USDZ, OBJ, STL).
